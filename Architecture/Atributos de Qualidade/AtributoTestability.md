## **Cenário de Qualidade de Testabilidade 1: Testes de Unidade**

- **Fonte do Estímulo**: A equipa de desenvolvimento realiza testes de unidade para garantir a funcionalidade correta dos componentes individuais.
- **Estímulo**: Execução de testes unitários em classes e métodos específicos do código fonte.
- **Ambiente**: Ambiente de desenvolvimento local ou de teste com acesso aos componentes do sistema ao nível do código.
- **Artefato**: Classes e métodos individuais do código fonte.
- **Resposta**: O sistema fornece feedback imediato sobre a funcionalidade correta de cada componente testado.
- **Medida da Resposta**: Os testes de unidade são executados automaticamente após cada compilação do código, e todas as falhas são corrigidas antes de enviar o código para revisão do mesmo.

## **Cenário de Qualidade de Testabilidade 2: Testes de Integração**

- **Fonte do Estímulo**: A equipa de desenvolvimento realiza testes para garantir a interação correta entre os diferentes componentes do sistema.
- **Estímulo**: Execução de testes de integração para verificar a comunicação e a integração entre os módulos do sistema.
- **Ambiente**: Ambiente de teste integrado com todos os componentes do sistema em funcionamento.
- **Artefato**: Interfaces entre os diferentes módulos e componentes do sistema.
- **Resposta**: O sistema fornece feedback sobre a integração correta entre os diferentes módulos, indicando se os dados são transmitidos e processados corretamente entre eles.
- **Medida da Resposta**: Os testes de integração são executados regularmente como parte do processo de integração contínua, e quaisquer problemas de integração são resolvidos antes de enviar o código para revisão.

## **Cenário de Qualidade de Testabilidade 3: Testes de Aceitação do Utilizador**

- **Fonte de Estímulo**: Utilizadores finais avaliam a adequação do sistema às suas necessidades e expectativas.
- **Estímulo**: Execução de testes de aceitação para validar se o sistema atende aos requisitos do utilizador e às especificações do projeto.
- **Ambiente**: Ambiente de teste que simula a plataforma, mas com dados de teste e sem impacto nos sistemas em produção.
- **Artefato**: Funcionalidades do sistema conforme especificado nos requisitos do utilizador e na documentação do projeto.
- **Resposta**: Recolha de feedback sobre se as funcionalidades atendem às expectativas dos utilizadores finais e aos critérios de aceitação definidos.
- **Medida da Resposta**: Os testes de aceitação são conduzidos em colaboração com os utilizadores finais, e quaisquer problemas ou feedback são documentados e tratados antes do lançamento da versão.

## **Cenário de Qualidade de Testabilidade 4: Testes de Cobertura do Código**

- **Fonte de Estímulo**: A equipa de desenvolvimento avalia a extensão dos testes e a cobertura do código.
- **Estímulo**: Análise da cobertura do código para determinar quais partes do código foram testadas e quais as partes que ainda precisam de testes adicionais.
- **Ambiente**: Ambiente de teste com acesso ao código fonte.
- **Artefato**: Código fonte do sistema.
- **Resposta**: Relatórios detalhados sobre a cobertura do código, indicando quais partes do código foram testadas e quais partes ainda precisam ser testadas.
- **Medida da Resposta**: A cobertura do código é monitorada regularmente, e quaisquer lacunas na cobertura do código são identificadas e abordadas para garantir uma cobertura de código abrangente.
